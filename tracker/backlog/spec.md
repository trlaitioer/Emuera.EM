# 延后项收集（backlog）

Date: 2026-09-27
Status: in-progress

## 问题/背景

与进行中的 effort 无关、或改动量需单独排期的缺陷与改进，既不属于当前票的范围，也没有其他 slug 可归。本目录是这类条目的中立归宿，也是 effort 收尾时未处理票的迁移目标。

范围限于「无 effort 归属」：与某 effort 同源的缺陷仍进该 effort 的 slug（issues/15~28 的先例）。

## 整体方案

- **落票**：`Status: needs-triage` 的最小票，正文含「现象 + 代码位置 + 完成标准」，方案可写「待评估」
- **查重**：落票前按现象关键词对标题与 `Type:` 做一次全库检索，命中则补进已有票正文
- **出口**：评估后就地开做，或转出——目标 effort 立新票，本票标 `superseded` 并在「影响」节注明承接方（文件不移动）
- **增长**：`issues/` 默认平铺，「未处理」与「已结」由 `Status:` 区分；终态票可移入 `closed/`

## 曾考虑的替代方案

1. 单一日志文件（一行一条）：放弃——与 issue-tracker.md「绝不要合并成单一的 tickets 文件」冲突，且状态要在行内二次维护，与头部 `Status:` 的单一真相来源重复
2. 只写进当前票的「顺带发现」节：放弃——该类条目与当前票的 effort 无关，按票读取时不可见；effort 收尾后也没有迁移依据
3. 不设本目录，一律就近立票：放弃——「与当前工作无关且需单独排期」这一类没有可归属的 effort slug

## 影响

- 未处理视图为查询而非清单（口径见 issue-tracker.md），不存清单故无需随票据增长维护
- issue-tracker.md 的 `Type:` 增加 `bug`，并补归属判据与视图口径
