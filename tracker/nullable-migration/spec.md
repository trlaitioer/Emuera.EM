# 迁移方案:C# 可空注解(Nullable)

## 问题/背景

目标:项目所有源码文件启用可空注解并消除 CS86xx 警告,最终把 `Emuera/Emuera.csproj` 的 `<Nullable>annotations</Nullable>` 改回 `<Nullable>enable</Nullable>`,迁移期间保持现有运行行为不变。

现状:

- 迁移本体已完成:[Emuera/Emuera.csproj](../../Emuera/Emuera.csproj) 为 `<Nullable>enable</Nullable>` 并带 `<WarningsAsErrors>nullable</WarningsAsErrors>`;[Emuera.Tests.csproj](../../Emuera.Tests/Emuera.Tests.csproj) 同样全量 `enable`(该工程不在 [Emuera.sln](../../Emuera.sln),闸门只在单独构建它时生效)
- CS86xx 为 0 条,两种声音后端配置分别确认:`Debug-NAudio`,以及 `Debug`(WMP,须用 VS 的 amd64 `MSBuild\Current\Bin\amd64\MSBuild.exe` 并清空 `*_PROXY`;32 位的 `MSBuild.exe` 会在 `ResolveComReference` 处报 MSB4216,proxy 变量名大小写重复会让 Roslyn 任务报 MSB3883)
- 非空断言(`!`)的收敛结果:`Emuera` 后缀断言 798 处、残差类 265 处,`Emuera.Tests` 161 处(测试工程按 [nullable-migration-14](issues/14-null-assertion-audit.md) 豁免逐点复核);逐站点判定分组与已失效站点见 [bang-sites.md](bang-sites.md),计数脚本为 [tools/count-bang-sites.ps1](tools/count-bang-sites.ps1)
- 存档读写的失败分档已落地:读取侧(文本档与二进制档)的内容损坏、越界与形状非法统一归 `FileEE`,二进制档头部仍按「头认不出来 ⇒ 不是二进制档」返 `null`(该档吞掉介质故障诊断的问题记 [nullable-migration-37](issues/37-header-catch-swallows-fileee.md));写入侧经 [Runtime/Utils/TempFileWriter.cs](../../Emuera/Runtime/Utils/TempFileWriter.cs) 先写同目录临时档再替换目标,故新内容落盘之前不动目标档;读取侧的 `LOADDATA`/`LOADGLOBAL` 把 MAP/XML/DT 先写进暂存状态、成功才与当前状态合成,读失败不再清掉当前存档扩展数据,清空施加在旧实例上(旧 map/DataTable 被清空而不是留着旧行,含被文件替换的那些,插件经 `PluginManager.GetDataTable` 持有的表同步变空)(`RemoveEM*` 只保留给 `RESETDATA`/`RESETGLOBAL`);抬头与原因行由 [Runtime/Script/ErrorReport.cs](../../Emuera/Runtime/Script/ErrorReport.cs) 统一
- 完成标准第 4 条按 [nullable-migration-19](issues/19-plugin-and-error-path-nulls.md) 的终态计:真实 era 游戏目录 + `-DEBUG` 窗口 + 坏输入报错文本(含 `FileEE` 档)已人工验收,该票为 `implemented`,依[当时的议题规范](https://github.com/trlaitioer/Emuera.EM/blob/502430abfbbacabc1d11d5558e21e43d91997851/docs/tracking/issue-tracker.md)「状态为 implemented 即视为验收通过」
- `Emuera.Tests` 全绿(853 条),其 CS86xx 亦为 0 条(实测只剩 CS8981 等非本迁移目标的警告)
- 非本迁移目标:`!` 之外的既有警告(CS8981 小写 alias、CS4014、CA1069/CA1806/CA1816/CA2019、WFO0003)
- 剩余范围:[nullable-migration-31](issues/31-assertion-honesty-nonnull-consumers.md) 断言诚实化的非空消费方、[nullable-migration-32](issues/32-assertion-audit-findings.md) 审计残余项、[nullable-migration-33](issues/33-constantdata-console-nullability.md) `ConstantData` 与 console 可空化、[nullable-migration-37](issues/37-header-catch-swallows-fileee.md) 二进制档头部 catch 吞 `FileEE`、[nullable-migration-39](issues/39-failed-load-state-rollback.md) 读档失败后普通变量与角色被复位

计数口径与复现:

- 复现命令 `dotnet build Emuera/Emuera.csproj -c Debug-NAudio -p:Platform=x64 --no-incremental -p:Nullable=enable`(csproj 恢复 `enable` 后该开关已冗余)
- 均为全量构建输出去重后的条数;去重有两种口径,只在 CS8618 上分叉:**完整警告行**(键为「文件路径 + (行,列) + 警告码 + 消息文本」,同一构造函数位置按未初始化字段逐条报告)与**文件+行+列+警告码**(更粗的位置口径)。各票保留自己的原始口径数字,「0 条」在两口径下同时成立
- `dotnet build` 会把同一条警告在内联与末尾汇总各输出一次,直接数行会翻倍;`Debug` 配置经 `MSBuild.exe` 构建时未见该重复

## 整体方案

差分按调用链与契约划分(2026-08-29 重切;原按目录分摊文件的 issues/01/02/04 废止,范围由链簇票承接):

- **契约票**:只改签名、字段声明与列表元素类型;允许跨文件修改,不启用新文件、不以清零 CS86xx 为验收;决策与影响面记录在票内
  - issues/05:方法调用链元素可空(`List<AExpression>` 贯通 FunctionMethod 签名 → override → `GetFunctionMethod` → RowArgs/ReduceArguments)
  - issues/06:横切契约(ExpressionMediator exm、GlobalStatic 字段、Config/Lang 叶子)
- **链簇票**:启用本链文件并清零该文件 CS86xx;为本链警告可修改票外文件的可空签名,但必须记录在票内正文
  - 核心规则:**签名跟链走,启用跟票走**
  - 建议顺序:解析链(issues/07)→ 变量与数据链(issues/10)→ 表达式与方法链(issues/08)→ 参数与指令链(issues/09)→ 进程与加载链(issues/11)→ UI 与外围(issues/12)
- **收尾**:issues/03 把 csproj 的 `<Nullable>annotations</Nullable>` 改回 `<Nullable>enable</Nullable>`
- **断言审计尾部**(迁移本体之后):issues/13 收敛 `!`(冗余删除与单点断言入口),issues/14 逐点复核对保留的断言给出结论,可达缺陷由 issues/15~22 承修

链簇票的 `blocked_by` 由上述顺序落成:每个上游链簇票为下游提供可空签名契约,故 10 阻塞于 07、11 阻塞于 07/10、12 阻塞于 06/07/10;08 的入边为 05/06/10,09 为 05/06(08 只在建议顺序上先于 09,不作为阻塞边)。顺序本身是建议而非机制约束,阻塞边只表达「先有契约再清警告」。

单文件通用步骤:给目标文件顶部加 `#nullable enable` → 构建 → 清零该文件 CS86xx。链簇票的启用范围:本链实测有 CS86xx 的文件必须启用并清零;同链当前零 CS86xx 的文件也一并加 `#nullable enable`,使「全库源码文件显式启用」可核对。生成文件(`*.Designer.cs`、`RikaichanAutogenerated.cs`)不加指令,由 csproj 收尾统一覆盖。

迁移期修复原则:

- 优先用 `?` 注解与 `null!` 保持现有运行行为,少加运行时判断
- `Emuera.Tests` 已就绪(见 `tracker/test-infrastructure/spec.md`);StrForm 的 `null!` 已替换 11/18(余 7 处省略参数占位,见 issues/05),后续文件迁移时同样以真检查或构造点保证替换 `!`
- 改动已启用文件后,默认构建的 CS86xx 必须仍为 0;出现新增即为回归,先清零再继续(默认构建只覆盖已启用文件,回归只会以 CS86xx 形式落在该文件上)

完成标准:

- 全量构建 CS86xx 警告为 0,两种声音后端配置分别确认(命令与踩坑见现状;两配置的差恰为互斥编译的 [Runtime/Utils/Sound.NAudio.cs](../../Emuera/Runtime/Utils/Sound.NAudio.cs) 与 [Runtime/Utils/Sound.WMP.cs](../../Emuera/Runtime/Utils/Sound.WMP.cs))
- `Emuera.Tests` 的 CS86xx 同样为 0(测试工程已全量 `enable`,由 issues/03 清尾)
- csproj 为 `<Nullable>enable</Nullable>` 且构建通过(非 CS86xx 的既有警告不在消除目标内,见现状)
- 迁移前后运行行为一致(用真实 era 游戏目录验证)

## 影响

- 全库 131 个源码文件启用可空注解与流分析(`Emuera/` 139 个受跟踪 `.cs` 减去 8 个不加指令的生成文件),csproj 恢复全量 enable
- 迁移期各文件顶部的 `#nullable enable` 未保留:csproj 翻转后由 `06560d44` 统一清除 131 个文件中的指令(此时已冗余),仅 `Runtime/Utils/Sound.WMP.cs` 残留 1 处(该文件只在 WMP 配置编译,不影响 NAudio 构建)
- 迁移期不改变运行行为;`Emuera.Tests` 测试套件作为回归安全网
