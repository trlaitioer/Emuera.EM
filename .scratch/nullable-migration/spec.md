# 迁移方案:C# 可空注解(Nullable)

Date: 2026-08-22
Status: in-progress

## 问题/背景

目标:项目所有源码文件启用可空注解并消除 CS86xx 警告,最终把 `Emuera/Emuera.csproj` 的 `<Nullable>annotations</Nullable>` 改回 `<Nullable>enable</Nullable>`,迁移期间保持现有运行行为不变。

现状:

- 项目级已改为 `<Nullable>annotations</Nullable>`(注解全局生效、流分析警告逐文件开启)
- 已启用 `#nullable enable` 且无 CS86xx 警告:`Runtime/Script/Data/StrForm.cs`(本迁移样例,18 处 `null!` 已全部消除,省略参数占位由 issues/05 贯通;该文件原记在 issues/01 名下,而 issues/01 已废止,适配由 issues/05 承担、收尾验收归 issues/03)、`Program.cs`、`UI/Game/StringStyle.cs`(后两者早于本迁移即已启用,见 git 历史)
- 剩余文件有 CS86xx 警告:issues/05(元素可空贯通)与 issues/06(横切契约声明)落地前为 99 个文件、1,799 条,落地后为 99 个文件、2,547 条;链簇票 issues/07、10、08 落地后为 66 个文件、1,821 条(2026-09-16 实测,与各票记录一致)。增量是契约本身引入的、按票由下游消化:元素可空化暴露的 `arguments[i]` 解引用(issues/08/09/11)与 Config 查找 API 变可空后的消费点(issues/12);链簇票开工时须重新实测本链数字
- CS86xx 之外尚有既有警告,不属于本迁移目标:CS8981(小写 alias 64 条,处理决策见 `.scratch/performance-optimization/issues/06-cs8981-alias.md`)、CS4014(`MainWindow.cs` 未 await 的 `ReloadPartialErb` 调用 1 条)、CA1069(13 条)、CA2208(4 条)、CA1806(2 条)、CA1816(1 条)、WFO0003(1 条)

计数口径:以上数字为全量构建输出去重后的警告条数。复现命令:`dotnet build Emuera/Emuera.csproj -c Debug-NAudio -p:Platform=x64 --no-incremental -p:Nullable=enable`。同一条警告在输出中会于内联与末尾汇总各出现一次,直接数行会翻倍(MSBuild 末尾的汇总行给出总数);该配置只编译 NAudio 后端文件,`Runtime/Utils/Sound.WMP.cs` 未纳入统计。迁移期的默认构建(不加 `-p:Nullable=enable`)只覆盖已启用文件,其 CS86xx 应恒为 0。issues/01、issues/04 中标注 2026-08-29 实测的历史计数按当时口径记录(输出原始行数,含重复)。

## 整体方案

差分按调用链与契约划分(2026-08-29 重切;原按目录分摊文件的 issues/01/02/04 废止,范围由链簇票承接):

- **契约票**:只改签名、字段声明与列表元素类型;允许跨文件修改,不启用新文件、不以清零 CS86xx 为验收;决策与影响面记录在票内
  - issues/05:方法调用链元素可空(`List<AExpression>` 贯通 FunctionMethod 签名 → override → `GetFunctionMethod` → RowArgs/ReduceArguments)
  - issues/06:横切契约(ExpressionMediator exm、GlobalStatic 字段、Config/Lang 叶子)
- **链簇票**:启用本链文件并清零该文件 CS86xx;为本链警告可修改票外文件的可空签名,但必须记录在票内正文
  - 核心规则:**签名跟链走,启用跟票走**
  - 建议顺序:解析链(issues/07)→ 变量与数据链(issues/10)→ 表达式与方法链(issues/08)→ 参数与指令链(issues/09)→ 进程与加载链(issues/11)→ UI 与外围(issues/12)
- **收尾**:issues/03 把 csproj 的 `<Nullable>annotations</Nullable>` 改回 `<Nullable>enable</Nullable>`

链簇票的 `Blocked by:` 由上述顺序落成:每个上游链簇票为下游提供可空签名契约,故 10 阻塞于 07、11 阻塞于 07/10、12 阻塞于 06/07/10;08 的入边为 05/06/10,09 为 05/06(08 只在建议顺序上先于 09,不作为阻塞边)。顺序本身是建议而非机制约束,阻塞边只表达「先有契约再清警告」。

单文件通用步骤:给目标文件顶部加 `#nullable enable` → 构建 → 清零该文件 CS86xx。链簇票的启用范围:本链实测有 CS86xx 的文件必须启用并清零;同链当前零 CS86xx 的文件也一并加 `#nullable enable`,使「全库源码文件显式启用」可核对。生成文件(`*.Designer.cs`、`RikaichanAutogenerated.cs`)不加指令,由 csproj 收尾统一覆盖。

迁移期修复原则:

- 优先用 `?` 注解与 `null!` 保持现有运行行为,少加运行时判断
- `Emuera.Tests` 已就绪(见 `.scratch/test-infrastructure/spec.md`);StrForm 的 `null!` 已替换 11/18(余 7 处省略参数占位,见 issues/05),后续文件迁移时同样以真检查或构造点保证替换 `!`
- 改动已启用文件后,默认构建的 CS86xx 必须仍为 0;出现新增即为回归,先清零再继续(默认构建只覆盖已启用文件,回归只会以 CS86xx 形式落在该文件上)

完成标准:

- 全量构建(`-p:Nullable=enable`)CS86xx 警告为 0,并按两种声音后端配置分别确认(`Debug-NAudio` 与 `Debug`,后者需用 VS 的 MSBuild 构建)
- `Emuera.Tests` 的 CS86xx 同样为 0(测试工程已全量 `enable`,由 issues/03 清尾)
- csproj 恢复 `<Nullable>enable</Nullable>` 后构建通过(CS8981 等非 CS86xx 既有警告不在消除目标内,见现状)
- 迁移前后运行行为一致(用真实 era 游戏目录验证)

## 影响

- 全库 99 个文件启用可空注解与流分析,csproj 恢复全量 enable
- 迁移期各文件顶部的 `#nullable enable` 在收尾后保留(与 `Program.cs`、`UI/Game/StringStyle.cs` 在 `annotations` 时期的既有做法一致,翻转后冗余但无害)
- 迁移期不改变运行行为;`Emuera.Tests` 测试套件作为回归安全网
