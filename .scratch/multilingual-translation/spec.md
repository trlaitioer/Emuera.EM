# 多语言翻译：代码覆盖层（spec）

> 状态：设计定稿（未实现）；修订记录见文末 Comments。
> 特性 slug：`multilingual-translation`
> 相关文档：`docs/architecture.md`、`docs/agents/domain.md`

---

## 1. 问题

eraBasic 游戏由 `csv/`（数据）与 `erb/`（脚本）构成，**文本是单一语言的**——作者写的是什么语言，游戏就是什么语言。社区想把这类游戏翻成中文/其它语言，但目前**没有任何面向「游戏内容」的多语言机制**：

- 解释器**已有**一套 UI 本地化机制：`Runtime/Utils/EvilMask/Lang.cs`（`[Translate]` 特性 + `[Managed]` 反射收集 + `lang/emuera-*.xml` 覆盖 + `SetLanguage`）。但它**只面向引擎自身的固定文本**（`Lang.UI.MainWindow.*`、`Lang.Error`、`Lang.MessageBox`），键是静态编译期 ID，无法表达「上下文」「出现次数」「歧义」，**不能用来翻译游戏内容**。
- 游戏文本分散在三个层面：
  1. **CSV 数据字段**（如 `*NAME.csv` → `Str1DConstantToken`、`NAME/CALLNAME/NICKNAME`）：结构化的显示名。
  2. **ERB 脚本字面量**（`"..."`=`LiteralStringWord`；`@"..."`=`StrFormWord`）：散落在代码里、与逻辑混在一起的叙述/对话/选项文本。
  3. **运行时计算串**：`STRDATA`/`DATAFORM` 等指令把模板求值成平铺 `string`（`GetStrValue()`），模板结构立即丢失；`STR`/`STRS` 等字符串变量只是朴素 `string[]`，**无法反溯来源模板**。
- **致命难点**：这些字符串不仅是「显示文本」，还会被用作**分支判断、动态 CALL、字符串比较、前缀匹配**。若整体翻译「存储值」，会破坏游戏逻辑。而「含内插的字符串」（如 `%CALLNAME%`）按渲染实例翻译又会按角色爆炸（几百上千条）。

目标：给解释器加**原生多语言翻译**，同时**完全兼容现有游戏脚本**。硬性红线：**原 `.erb`/`.csv` 一字不改**，翻译层完全可选、出错回退原版。

## 2. 定稿方案（v1：代码覆盖层，函数级）

### 一句话概括

**不翻译字符串**，而是通过**旁挂的覆盖文件**（`.erbx`）直接**替换游戏函数**来实现翻译——把负责输出文本/逻辑的函数覆写成译版。原 `.erb` 零改动，完全兼容现有游戏脚本。字符串级翻译作为后续可拓展项，本期不做。

### 2.1 文件形态与装载

- 覆盖文件树：`tl/` 下按语言一级分目录，目录内**镜像**游戏数据目录结构；本期映射为 `tl/<lang>/erb/X.erbx ↔ erb/X.erb`（`tl/<lang>/csv/` 等为后续数据层翻译预留）。语言列表 = `tl/` 下的一级子目录名。
- 函数级覆盖文件扩展名 **`.erbx`**（原始 `.erb` 的翻译版）。
- 片段级覆盖（后续）使用**另一种扩展名**，与 `.erbx` 区分（见 §3.1）。
- `.erbx` 内容为普通 eraBasic，直接 `@FUNCTION_NAME` 定义同名函数来覆盖。

**装载改造点（大方向；具体装载逻辑后续补充，已核实的约束记入 §4.1）：**
- `Config.getFiles`（`Emuera/Runtime/Config/Config.cs`，私有静态方法；过滤即其中的 `if (Path.GetExtension(filepaths[i]).Length <= 4)` 判断）：**移除该过滤**。它是 .NET Framework 通配符怪癖的防护（Framework 下 `*.xls` 会连 `book.xlsx` 一起命中；MS 文档明确标注该行为 ".NET Framework only"，.NET 5+ 已改为扩展名精确匹配）。本项目已是 .NET 10，`*.ERB`/`CHARA*.CSV`/`*.ERH` 等现有调用方行为不变；`.erbx` 用显式 `*.erbx` 模式收集。（另一条 8.3 短名怪癖仅影响含中置通配符的模式，本项目模式均为尾置通配符，不受影响。）
- `tl/` 根目录与 `erb/` 同级：`Program.SetDirPaths` 内 `ErbDir = Path.Combine(ExeDir, "erb")`（`Program.cs`），tl 根同理取 `ExeDir + "tl\\"`。
- 在 ERB 装载流程（`ErbLoader.LoadErbDir`，`ErbLoader.cs`）中加入 `tl/<语言>/erb/` 的扫描、`.erbx` 解析与原 `.erb` 加载时的覆盖跳过；`.ERH`/`.erd`/`.csv` 加载器（`ErhLoader.LoadHeaderFiles` / `ErhLoader.PrepareERDFileNames`，`ErhLoader.cs`）本期不动。

### 2.2 覆盖机制（函数级，核心）

- **全量替换**：当 `.erbx` 定义了 `@FUNCTION_NAME`，则原 `.erb` 中的同名函数被**完全替换**，其函数体**不再注册/不再解析**（翻译版全权接管）。
- **主机制 = 「跳过」**：先加载 `.erbx` 覆盖函数的标签，建一张「覆盖表：函数名 → 覆盖标签」。加载 `.erb` 时，凡函数名命中覆盖表 → **跳过该原函数的注册与解析**；未命中 → 照常注册。覆盖表中存在、但原 `.erb` 中不存在的函数名不是覆盖——按普通函数注册（允许的翻译辅助函数，见 §2.4）。跳过是唯一充分机制，对**事件函数（`@EVENT*`）也必须生效**——事件函数走 `eventLabelDic`（`#PRI`/`#LATER` 分桶并列执行，没有「覆盖」语义），不靠跳过就会与原版同时运行。
- **统一插入点**（关键，已被源码证实）：CALL/跳转解析在 parse-time（`ErbLoader.setJumpTo` 逐指令调用 CALL 系指令的 `SetJumpTo`，`Instraction.Child.cs` 中的实现内调用 `GetFunctionMethod(GlobalStatic.LabelDictionary, ...)`）与运行时（`Process.CalledFunction.CallFunction`）**都走** `IdentifierDictionary.GetFunctionMethod` → `GetNonEventLabel` → `noneventLabelDic[name]`。因此只要让覆盖标签成为 `noneventLabelDic[name]` 的**唯一项**，CALL/跳转就会自动定向到覆盖版。
- **作用域与裁决**：覆盖**按名全局**生效——eraBasic 函数命名空间本身就是全局按名（`noneventLabelDic` 单一扁平字典、大小写不敏感比较），「按文件限定」在语言语义中没有对应物，镜像树只是译者侧的组织约定。覆盖裁决**不依赖加载顺序**：并行装载（含 `tl/`）下只按「是否存在覆盖」判定；`.erbx` 之间的重复覆盖定义固定按**重复定义报错**处理，不走同名兼容配置（翻译包内部冲突属于内容错误，无兼容语义）；原 `.erb` 侧同名处理受同名兼容配置影响（`performance-optimization/issues/04-parse-parallel.md`）。`*#*` 目录先加载（`FileIndex` 更小）对覆盖无影响——主机制是跳过，不依赖顺序。
- 附带说明（非机制依赖）：非事件函数的同名处理是「先加载生效」（`LabelDictionary.SortLabels` 取排序后 `list[0]`，排序首键为 `FunctionLabelLine.CompareTo` 的 `FileIndex`）。跳过落实后 `LabelDictionary` **无需任何改动**（并行装载对同名处理的收紧属 `performance-optimization/issues/04-parse-parallel` 范围）。

### 2.3 语言选择与持久化

- 新增 `ConfigCode` 键（如 `TranslationLang`），取值：`未选择`（默认）/ `原版` / `tl/` 下的语言目录名。配置只进常规配置文件，**绝不进游戏存档**。
- 启动时检测 `tl/` 是否存在：不存在 → 完全无覆盖、原版运行、不询问。
- 目标行为：仅当配置为「未选择」时弹选择菜单；`原版` → 直接原版运行；某语言 → 直接沿用该语言。切换语言需重启生效，配套要在窗口增加「更换语言（重启生效）」菜单。
- v1 过渡：「更换语言」窗口菜单尚未实现，先**每次启动都弹选择菜单**（复用 `PRINTBUTTON` 系交互，可点击、可输入序号选择），预选上次选择，选项含各语言与「原版」。
- 语言选择必须发生在 ERB 装载之前（覆盖表是装载期决策）。

### 2.4 兼容与安全红线（不可违背）

- 原 `.erb` / `.csv` **零改动**。
- **翻译单元语义红线**：只翻「展示路径」，绝不进「计算 / 存储 / 比较」路径。字符串可被存储 / 比较 / 动态 CALL 复用，因此字符串级翻译只能作用于「即将被显示」的模板；数据字段翻译另论（见 §3.4）。
- `tl/` 整体是**额外挂载**：加载逻辑为「**存在才加载**」。`.erbx` 缺失 / 为空是**正常状态**（对应函数无覆盖、原版运行），不视为错误、无需回退。
- **允许定义原版不存在的函数**，作为特定翻译语言的辅助函数；按普通函数注册，不参与覆盖跳过。
- 装载期可发现的错误（`.erbx` 语法错误等）→ **整体弃用该文件、回退原版**（按文件回滚已注册标签），警告但不崩溃。
- 已知限制：覆盖版与原函数的**签名不一致**（参数个数/类型、`#FUNCTION` 返回类型不同）无法凭 `.erbx` 自身在装载期发现，会在调用方 parse 或运行期报错，**无法自动回退**；以装载期签名校验缓解（见 §2.5）。
- 覆盖层**完全可选**：不装 `tl/` 就是原版游戏。

### 2.5 签名校验（已拍板）

- **问题**：原函数被完全跳过后，其参数声明、`#DIM`、`#FUNCTION` 返回类型不再参与解析；覆盖版若签名不一致（参数个数/类型、`#FUNCTION` 返回类型），调用方会在 parse 或运行期报错且无法自动回退（见 §2.4 已知限制）。
- **方案（v1，串行等价实现）**：装载期对被覆盖原函数解析头部（`@NAME,ARGS` 头行 + 其后的 `#FUNCTION`/`#DIM` 等属性行）并与覆盖版比对。比对对象只需「调用方可见契约」（参数个数/类型、`#FUNCTION` 返回类型、BYREF）；LOCAL/ARG 等函数内局部尺寸无需比对（原函数被跳过后由覆盖版自行决定）。只对被覆盖函数各解析一次头部，开销可忽略。
- **与并行装载的衔接**：函数级并行装载采用「解析签名 → 确定 label（覆盖裁决、签名校验）→ 解析函数体（含 CALL 跳转处理）」三阶段管线，`tl/` 复用同一管线；本节方案即阶段①/②逻辑的串行等价实现，迁移时直接搬入。管线设计详见 `performance-optimization/issues/04-parse-parallel.md`。

## 3. 后续（已定搁置项）

> 以下各项已定稿但搁置：因**范围控制 / 风险 / 价值权衡**推迟到后续阶段；「已确认的细节」为定论，实现时直接采用。

### 3.1 片段级内容哈希覆盖（搁置）

- **概述**：能精准改「某一条调用 / 赋值 / 输出」而不动整个函数，是「代码覆盖」更高一层的形态；用于只改局部而不用整函数重写。
- **已确认的细节**：
  1. 与函数级覆盖**拆分到不同后缀名文件**（`.erbx` 之外的另一种扩展名）。
  2. 片段单位 = **单条逻辑行**（`LogicalLineParser` 切出的最小执行单元）。
  3. 哈希对象 = **去除首尾空白 + 去除行尾注释之后的**行文本（对缩进 / 注释稳健）。
  4. 同一函数内「内容相同」的重复逻辑行 → 用**出现顺序后缀 `_1` / `_2`** 区分（不与相同原文合并）。
  5. 覆盖体形成后**拼进原函数、替换原代码**（作为函数体一部分，而非可独立 CALL 的函数）。
  6. 覆盖标签名 `@__FUNCNAME_<hash>` **合法**：标签名校验只拦符号与首字符数字（`IdentifierDictionary.cs` 的 `badSymbolAsIdentifier` 符号黑名单不含 `_`，故字母/数字/`_` 均合法），整个标识符会被当作一个 `IdentifierWord` 读入、不报错。
- **需要新做的解释器能力**：现有命名空间按「名字 + `FileIndex`」去重，**没有「按内容哈希」概念**；要新做「按内容哈希改写函数体」层——在 `ErbLoader.nestCheck`（IF/REPEAT 等嵌套对应检查）与 `ErbLoader.setJumpTo`（跳转回填）之前，对每个 `FunctionLabelLine` 的指令链按哈希逐条匹配、替换成覆盖体。这是一次不小的解释器手术。
- **hash 算法与截断长度**：推荐 sha256（或同类快速安全哈希）截断到 **≥32 hex（128bit）**、或直接用完整 64 hex；**不要砍到 16**——代码覆盖的碰撞后果（覆盖错代码）比字符串翻译重。另一方面，片段级有「函数名前缀」作限定，单函数内碰撞概率没那么高，只有 `IF` / `ELSE` / `THEN` 等极短代码才可能碰撞、而翻译一般不改这些。**结论：先搁置，做完函数级覆盖再重估。**

### 3.2 字符串模板层 / 简化翻译（搁置）

- **概述**：翻译**作者级模板**而非最终渲染串；能批量、低门槛翻译，并支持占位符重排（JA 主宾谓 → ZH 主谓宾）。
- **已确认的细节**：
  1. 拦截点 = **`StrFormTerm` 求值前**（`Term.cs` 的 `StrFormTerm`，内含 `StrForm`、即 `strs[]/terms[]`），且必须在 `StrForm.Restructure`（常量折叠，`StrForm.cs`）与 `GetStrValue()` 求值**之前**；一旦展平成 `string`（打印 / 写入变量）模板即丢失，字符串变量（`VariableData` 内的朴素 `string[]` 系字段）无来源元数据、无法反溯。
  2. 翻译单位 = **作者模板**（含占位符的 `@"..."` 或纯 `"..."`），一个模板一个键；**按模板缓存**（Ren'py `_translations` dict 思想），避免按渲染实例爆炸。
  3. 占位符**按名**引用、可**乱序**（这是 JA→ZH 质量过关的关键）；命名用「源码写法规范化名」：`%CALLNAME%`→`CALLNAME`、`%TARGET.NAME%`→`TARGET.NAME`、三连符号 `+++`/`***`/`===`/`///`/`$$$`、`%ITEMNAME:x%` 统一归一。
  4. 普通 `"..."`（`LiteralStringWord`，无内插）最简单安全；`@"..."`（`StrFormWord`）最难——只能改字面段、绝不能动 `%` / `{}` / `\@\@` 定界符与占位表达式（否则 `NotFoundCorresponding`）。
  5. 对齐宽度按所选语言字节算（`LangManager.GetStrlenLang`），译文变长会影响 `%var%` / `{var}` 对齐。
- **与代码覆盖的关系**：较新游戏的字符串拼接与 `PRINT` 系输出的使用规模差别不大，代码覆盖即可顺带覆盖大多数字符串场景，因此**本期先做纯代码覆盖**，字符串模板层搁置、作为后续可拓展项（不彻底否决）。

### 3.3 调用原版逃逸口（后续再加）

- **概述**：让覆盖体能**调用「未被覆盖的原函数本体」**，从而做「局部包装 / 追加改动」而非整段重写；原文更新时只需补差异。
- **已确认**：v1 先做**全量替换**（原函数不被注册 / 不解析）；逃逸口后续再加。

### 3.4 CSV 数据字段翻译（二期）

- **概述**：`*NAME.csv`、`ITEMNAME`、性格名、`CDFLAGNAME`、角色 `NAME/CALLNAME/NICKNAME` 等数据字段，既有显示名、又被用作分支 / 比较 / 动态 CALL。
- **结论**：本期不做。起步采用「完全不翻数据字段」（最安全）；预留「按列标记『纯显示列』、只翻渲染路径」作为二期方案；**不做**「显示与比较/分支/CALL 侧全局一致」的一致性翻译（最复杂、最危险）。

### 3.5 覆盖模板生成工具（搁置）

- 扫描 `erb/` 输出 `.erbx` 骨架、供译者逐个填充；v1 非必需（译者直接编写 `.erbx`）。若恢复，可一并承担骨架保证与签名 lint（配合 §2.5）。

### 3.6 语言元数据文件（后续拓展）

- v1 直接用 `tl/` 下目录名作语言键与显示名；后续可增加 `.json`/`.toml`/`.ini`/`.config` 等元数据文件（显示名、作者等）。

### 3.7 窗口「更换语言（重启生效）」菜单（v1 后补）

- 菜单落地后，语言选择回到目标行为：仅配置为「未选择」时弹选择菜单（见 §2.3）。

## 4. 未决项（开放问题）

### 4.1 装载细节（待补充）

具体装载逻辑后续补充。已从源码核实、设计时必须满足的约束：
- `LoadErbDir` 在装载任何文件之前会 `labelDic.RemoveAll()`（`ErbLoader.cs`）：任何「一次性预载 `.erbx` 标签」的方案都会被运行期重载清空，`tl/` 装载必须放在 `LoadErbDir` 流程内部。
- 运行期存在 ERB 重载：`Process.ReloadErb`（走 `LoadErbDir`）与 `Process.ReloadPartialErb`（走 `ErbLoader.LoadErbList`）；`LoadErbList` 与 `LoadErbDir` 最终都汇入 per-file 的 `ErbLoader.loadErb`，覆盖跳过门控应实现在 `loadErb` 内，使所有装载路径（含 AnalysisMode 走的 `LoadErbList`）一致生效。
- ERB/CSV 走 `Preload` 内存缓存（启动与重载各一处 `Preload.Load(Program.ErbDir/CsvDir)`：`EmueraConsole` 初始化路径与 `Process.ReloadErb`），`tl/` 树需同样纳入。
- 语言选择须先于 ERB 装载完成。
- 覆盖裁决按名跳过、不依赖加载顺序（见 §2.2），天然兼容并行装载；`tl/` 树届时同样并行装载并复用函数级管线（见 §2.5 与 `performance-optimization/issues/04-parse-parallel.md`）。原 `.erb` 内同名函数在并行装载下的裁决（同名兼容配置）属该 issue 范围，与覆盖机制无关。

### 4.2 片段级 hash 键基准（3.1 启动时定）

哈希算「原始源码行（读入那一瞬、宏展开前）+ 去空白」还是「引擎解析后逻辑行」：倾向前者——译者照抄即可得 hash，生成工具可显示每行 hash；待 3.1 启动时拍板。

### 4.3 字符串模板层的作用边界（3.2 启动时定）

模板层是否只处理「未被覆盖的函数」里的模板：一个函数一旦被覆盖，内部字符串是否全交给覆盖版、模板层不再管。未拍板。

### 4.4 调用原版逃逸口的实现方式（3.3 启动时定）

备选：①`CALL ORIGINAL:F` 之类特殊语法；②`#DIM` 特殊标记（复用原解析逻辑）；③在函数作用域直接暴露一个特殊名称。未拍板。

## 5. 被否决的方案与否决原因

| 方案 | 结论 | 否决原因 |
|---|---|---|
| **复用现有 UI 本地化 `Lang` 机制** | 否决 | `Lang` 是「静态键 + 编译期 ID」：`[Translate]` 特性写在引擎 C# 源码里、反射收集；翻译文件 `lang/emuera-*.xml` 的 `id` 与内容无感知。无法表达「上下文」「出现次数」，无法成键消歧，**只能翻引擎固定文本**。只复用其**外围管线**（`useLanguage`/`LangManager.setEncode` 编码、`GetLangList` 语言枚举、`SetLanguage` 流程、「未覆盖回退原文」思想）。 |
| **数据层替换**（翻译 CSV/常量字符串的存储值） | 否决 | 字段名（如 `ITEMNAME`、性格名、`CDFLAGNAME`、`NAME`）会被**分支判断 / 动态 CALL / 字符串比较 / 前缀匹配**使用，整体翻会破坏逻辑；且某些名词「按字段名开头匹配」时会译不得。 |
| **展示层大字典**（对所有最终展示字符串做输出前替换） | 否决 | ①含插值串 `%CALLNAME%` 按渲染实例翻译会**按角色爆炸**（几百上千条）；②`STRDATA`/`DATAFORM` 算出的成品串**模板已丢失**、字典无法按模板定位；③本质是「最终串字典 + 输出前替换」，**性能与覆盖都很差**。 |
| **字符串模板层**（Ren'py 式：`StrFormTerm` 求值前按作者模板键、按名重排占位符、缓存） | 部分采用、搁置 | 本可作主机制，但与「代码覆盖」并存需两套机制。「重排占位符」能保 JA→ZH 质量，但较新游戏中字符串拼接与 `PRINT` 系输出的使用规模差别不大，代码覆盖即可顺带覆盖大多数字符串场景，因此**本期先做纯代码覆盖**，字符串模板层搁置（等后续找到好方式再拓展）。 |
| **片段级内容哈希覆盖 一期就做** | 搁置 | 现有命名空间按「名字 + `FileIndex`」去重，**完全没有「按内容哈希替换语句」的概念**，需新做「按内容哈希改写函数体」层（在 `nestCheck`/`setJumpTo` 之前替换指令链），是一次不小的解释器手术。先做函数级覆盖验证价值。 |
| **调用原版逃逸口** | 搁置 | 一期做全量替换即可；调用原版接口（`#DIM` 或函数作用域特殊名）后续再加。 |
| **hash 截断到 ≤16 hex** | 否决（本期限整体搁置） | 这是**代码覆盖**，碰撞后果（覆盖错代码）比字符串翻译重得多；但本期先不做片段级，且片段级有「函数名前缀」限定，单函数内短代码（`IF`/`THEN` 等）才可能碰撞且翻译一般不改。**先搁置，做完函数级覆盖再重估。** |
| **用行号作翻译键** | 否决 | 行号极脆弱，原文件一改就大量失效；应改用内容哈希（对文本改动稳健、对行号移动稳健）。 |
| **自动改写/修改源文件**（破坏性） | 否决 | 违反「兼容现有游戏脚本」红线；翻译必须纯旁挂覆盖、原文件一字不改。 |

## 6. 影响范围

### 6.1 需要改动的文件（改造点清单）

| 文件 | 改动 | 风险 |
|---|---|---|
| `Emuera/Runtime/Config/Config.cs`（`getFiles`） | 移除「扩展名长度 ≤4」过滤（.NET 10 下对现有模式无行为差异） | 低 |
| `Emuera/Runtime/Config/ConfigCode.cs` / `ConfigData.cs` / `Config.cs` | 新增 `TranslationLang` 配置键（解析/保存/默认值 `未选择`；只进配置文件、绝不进游戏存档） | 低 |
| `Emuera/Runtime/Script/Loader/ErbLoader.cs`（`LoadErbDir`/`loadErb`） | `tl/<语言>/erb/` 扫描、`.erbx` 函数加载、`loadErb`（per-file）内跳过被覆盖函数；需覆盖运行期重载路径（`Process.ReloadErb`/`Process.ReloadPartialErb`，经 `ErbLoader.LoadErbList`）与 `Preload.Load` 的启动/重载两处调用（`EmueraConsole`/`Process`）——细节见 §4.1 | 中 |
| `Emuera/Runtime/Script/Data/LabelDictionary.cs` | **无需改动**（跳过机制足够，见 §2.2） | — |
| 新增 `Emuera/Runtime/.../Translation.cs`（或类似） | 覆盖表、语言选择、签名校验（§2.5）、`.erbx` 校验与回退逻辑 | 中 |
| `Emuera/Program.cs` 启动流程 | 语言选择、装载覆盖文件 | 低 |

新增用户可见文案（语言选择、覆盖警告）需补 `trsl`/`trerror` 资源。

### 6.2 兼容性影响面

- **对现有游戏**：`tl/` 目录不存在 → **零影响**，完全按原版运行。只需旁挂 `tl/<language>/*.erbx` 才会生效。
- **对原 `.erb`/`.csv`**：完全不变。
- 风险缓解：任何 `.erbx` 的语法错误 / 引用不存在的函数 / 空文件，一律**回退原版**，不影响游戏启动。

### 6.3 性能影响

- 覆盖表在**装载期**构建（一次）。
- 被覆盖的函数**完全不解析**，节省 parse 时间（且避免原函数潜在问题）。
- 运行期无额外开销（CALL/跳转走原有 `noneventLabelDic` 查找，只是键指向覆盖标签）。

### 6.4 不涉及的范围（边界）

- 除装载流程外不改动解释器核心（含 `LabelDictionary`、跳转解析）。
- 不处理 CSV 数据字段翻译（见 §3.4）。
- 不做字符串模板层（见 §3.2）。
- 不做片段级覆盖、逃逸口、hash 算法落地（见 §3.1/§3.3）。

### 6.5 安全与数据风险

- 翻译覆盖层是**旁挂**，不会写入或改动任何游戏源文件。
- 唯一需要小心的是 `.erbx` 语法校验与回退逻辑，确保「翻译文件损坏 → 回退原版而非崩溃」。
