# 等宽网格渲染模式:换字体不破坏排版

Status: needs-triage
Type: task

## 背景

- 表现(windowX=1600 / FontSize=14):黑体显示正常;切换 JetBrains Maple Mono 后左侧菜单实测变宽,与游戏按字符数定位的右侧栏重叠。
- 根因:游戏按全角/半角字符数排版,而 Emuera 按 `StringMeasure.GetDisplayLength` 对当前字体实测像素落笔。Maple Mono 的 ASCII 前进宽(~0.6em,汉字 ≈ 2×)大于黑体类字体假设的 0.5em,每个 ASCII 字符的漂移逐行累计即重叠。黑体正常是因其实测宽度 ≈ 作者假设的网格。
- 现无任何等宽强制/字符宽度表机制。

## 方案(字体自适应网格)

- 新增配置开关(默认关,现有比例渲染行为不变);
- 开启时:`w_half` = 实测基准 ASCII 字符('M' 或 '0')的前进宽,`w_full` = 2 × `w_half`(锁定 2:1);`GetDisplayLength` 与落笔前进改为按字符全角/半角分类 × 单元宽计算,不逐串实测;
- Maple Mono 下测得 ≈0.6em/1.2em,与其设计度量一致——不重叠、不挤压、无漂移;黑体下测得 ≈0.5em/1.0em,与现状逐像素一致;
- 已知取舍:真正的比例字体(如微软雅黑)开启后拉丁字符统一拉齐到 `w_half`,观感变等宽;取舍说明写入文档,开关默认值未确定、随 triage 定夺;
- 与 issues/02(DPI 缩放)兼容:网格单元宽乘 DPI scale。

## 验收

- 默认关:与现状一致;
- 黑体开启:与现状逐像素一致;
- Maple Mono 开启:字符计数定位的版面(右侧栏)与黑体时相对布局一致,无重叠、无叠墨(用例截图对比);
- 构建通过。
